# WatchLog 0.11.0: All clusters and fleets

One WatchLog holds every Kubernetes cluster and Linux server fleet you run. Pro now shows all of
them on one page: what needs attention anywhere, most urgent first, with the same problem in
staging and production shown once.

## What's new

### All clusters and fleets (Pro)

- **One page for everything:** a status sentence, four numbers (clusters and fleets by status,
  nodes and servers not reporting, open problems, alerts sent by channel), and a filter for
  Kubernetes or Server fleets that applies to every section.
- **Needs attention, everywhere:** every open problem from every cluster and fleet, critical
  first, each with its probable-cause line and a chip for each place it is in.
- **The same problem in two places is one row:** the same alert rule on the same workload name
  (the same unit, process group or container on servers), started within 30 minutes of each
  other. Nothing fuzzier.
- **Clusters and fleets, side by side:** status, agents reporting, a CPU sparkline, memory, open
  problems, What changed and alerts sent, worst first. A row opens its own Overview.
- **What changed across all of them,** ranked together, and **housekeeping:** old agents,
  failing alert channels, clusters with no channel, eBPF off.
- **Getting there:** the first item in the sidebar and in the cluster switcher. Pro organizations
  with two or more clusters and fleets open on it after signing in.
- **Fast at any size:** one metrics query per metric for the whole organization; 50 clusters and
  fleets answer in about 30 ms.
- **API and MCP:** `GET /api/v1/overview/all` and the `get_all_clusters` tool, for "is anything
  wrong anywhere?".

Cloud Free and the self-hosted Community edition see an upgrade page in its place. Everything
else stays as it is on every plan.

## Upgrading

No manual steps. Nothing changes in the agents, the Helm charts or the Compose file.
