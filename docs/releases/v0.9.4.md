# WatchLog 0.9.4

**The learning week of What changed, shown.** What changed (Pro, in WatchLog Cloud) learns
each metric's usual week for 7 days before it lists anything. Until now the page said so in
one line. It now shows what is happening, why it takes a week and when it is ready
([ADR-216](https://github.com/watchlog-light/watchlog/blob/v0.9.4/docs/DECISIONS.md)).
Learning itself is unchanged: the same 7 days, the same statistics. Nothing changes for
self-hosted installs except the page they see in place of What changed.

## What changed

- **The learning page,** for Kubernetes clusters and Server fleets, in the list's place for a
  cluster's first 7 days:
  - "Learning · day 3 of 7", and "Ready on Wed 25 Nov, about 14:10" in your own time zone,
    with the time to go;
  - the series it is reading, in your platform's words (nodes, workloads and applications; or
    servers, services, process groups, containers and applications);
  - the week it is learning: the 168 hours of the week, each learned, this hour, or not seen
    yet, from the baselines that exist. An hour your agents sent nothing in stays empty;
  - what happens next, and what already works today (alerts, probable cause, Egress watch,
    the service map), with links.
- **Email me when it's ready.** One email to your own address the minute the list turns on,
  for that cluster or fleet. Every member can ask, Viewers too; the button shows its state and
  undoes it. Nothing is sent if the organization has left Pro by then.
- **Later joiners.** When the list is on and a server or workload that joined afterwards is
  still inside its own 7 days, a line above the list says how many series still learn and when
  the last is ready.
- **The same, in small:** an alert's "What changed around it" card is one line with the ready
  date; the navigation shows "day 3/7" beside What changed; Plan & billing says after Checkout
  that What changed starts learning and is ready 7 days later.
- **The upgrade page** (what Cloud Free and a self-hosted install see in place of What
  changed) leads with the same picture, waiting and labelled "Not learning yet": nothing is
  learned on Free. On Cloud Free it says "Upgrade today and it's ready on <date>", with the
  real date. A self-hosted install sees no date, since What changed runs in WatchLog Cloud.
  After Checkout the page turns into the learning page by itself.
- **API and MCP.** `GET /api/v1/what-changed`'s `learning` object now carries `day`,
  `hoursLearned`, `hoursTotal`, `week`, `series` and `emailWhenReady` beside `learning`,
  `since` and `until` (an addition; nothing was removed). MCP `get_what_changed` reports when
  learning started, when it is ready, the day and the hours learned.
- **Motion and accessibility.** The animations are SVG and CSS only, stop with reduced motion
  (nothing is lost with them), and pause while the tab is hidden. With the page open they keep
  the browser's main thread 0.25 % busy, against 0.20 % with no animation at all. The week's
  grid has a text form for screen readers.

## Fixed

- The What changed page called a Server fleet "Docker" beside its name. It says "Servers".

## Upgrading

No manual steps. One database migration runs by itself (two small tables for What changed's
learning week; empty in self-hosted installs). Agents are unchanged: 0.9.2 agents need no
upgrade. In WatchLog Cloud, a cluster that is in its learning week during the update shows
the hours it has already learned after the anomaly-worker's next hourly run.
