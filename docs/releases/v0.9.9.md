# WatchLog 0.9.9

Setting a password says what is wrong while you type, in self-hosted installs and WatchLog Cloud
alike. In Cloud, password sign-in is also checked by Cloudflare Turnstile, out of sight for most
people. Nothing changes for agents, clusters or servers.

## Changed

- **The password field says what it wants, as you type.** Wherever a password is set (first-run
  setup, a reset link, an invite; in Cloud also sign-up) the "Weak / Strong" bar is gone. It
  judged the mix of character kinds, so it called a long passphrase weak and never said why a
  password was refused. Under the field there is now a short checklist that ticks live: "At
  least 10 characters" and, in Cloud, "Not found in known leaked passwords". There are no rules
  about symbols or capitals
  ([ADR-175](https://github.com/watchlog-light/watchlog/blob/v0.9.9/docs/DECISIONS.md)).
- **Show, hide and suggest.** The field has a show/hide button that works from the keyboard and
  is named for screen readers, and "Suggest a strong password", which fills in four random
  words and shows them. Password managers are told it is a new password.
- **Errors sit under the field they are about and say what to do.** For example: "This password
  is in a list of leaked passwords, so attackers try it first. Pick a different one: three or
  four random words work well." The cursor goes to that field and the other fields keep what
  you typed. No button is greyed out without a reason: pressing it takes you to the first
  problem.
- **Ending a silence offers Undo.** "Silence ended. Its alerts send messages again." comes with
  one button that silences the same alerts again until the same time.

## Fixed

- **A reset link or an invite asked for 12 characters; the server asks for 10.** A password of
  10 or 11 characters was refused by the page although the server would have taken it. The
  pages now show the server's number.

## WatchLog Cloud

- **Leaked passwords are checked while you type.** The page sends the first 5 characters of the
  password's hash to WatchLog Cloud and compares the rest itself, so neither the password nor
  its hash leaves your browser, and your browser calls no third party. When the list can't be
  reached the item reads "Couldn't check right now; we'll check when you continue", and the
  server decides, as it always did.
- **A leaked password no longer costs you the human check.** Sign-up looks at the password
  first, so after picking another one you don't solve Turnstile again.
- **Turnstile on password sign-in.** Most people see nothing; a visit Cloudflare finds
  suspicious gets a checkbox. If your network blocks Cloudflare you can still sign in, with
  fewer tries allowed: 5 per account and 10 per address in 15 minutes. GitHub and Google
  sign-in, the two-factor step, API tokens, MCP and the agents are not affected.
- **The sign-up page names servers too:** "Kubernetes or Linux servers: pick one, copy one
  command"; on a server, Docker containers are picked up as well.

Self-hosted installs have no Turnstile and make no leaked-password call: the field shows the
length rule, the show/hide button and the suggestion.

## Upgrading

No manual steps. One database migration runs by itself: it adds the time of each user's last
sign-in (used by Cloud's own administration; empty and unused in a self-hosted install). Agents
are unchanged: 0.9.2 agents need no upgrade.

Running the Cloud edition yourself with Turnstile: create the widget in Managed mode, so the
sign-in page stays quiet (see
[configuration](https://github.com/watchlog-light/watchlog/blob/v0.9.9/docs/site/configuration.md)).
