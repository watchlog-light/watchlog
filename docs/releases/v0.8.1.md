# WatchLog 0.8.1

A fix for WatchLog Cloud's plans: Pro features now always follow the plan.

## Fixed

- **A Free org could keep Pro features.** Staff could set an org's Pro features separately from its plan, so an org moved from Pro to Free could still read "Free plan" in the sidebar while What changed showed the Pro page and learned for it. Now Pro and Enterprise have the Pro features and Free has none, everywhere: the sidebar, What changed (the page, the alert card, the API and the MCP tool) and the anomaly-worker. A write that asks for anything else is refused (ADR-205).
- **The sidebar once billing is live.** On Cloud Free, the plan's link reads "Upgrade to Pro · $1 per node" once billing is live, instead of "Try Pro, free during beta". It still opens Plan & billing.
- **The upgrade page's fine print** with billing live now has its missing space before "Paid through Stripe".

Community installations have no plans and see no change.

## Upgrading

No manual steps: one automatic migration. On Cloud, an org whose Pro features disagree with its plan takes its plan's value, and a database check keeps the two equal. An org that loses Pro features this way stops being scored by What changed at once; its baselines are kept 30 days, as after any downgrade. On a self-hosted install the migration changes nothing. Agents don't change. Kubernetes: `helm upgrade … --version 0.8.1 --reuse-values`. Docker: set `WATCHLOG_VERSION=0.8.1`, then `docker compose pull && docker compose up -d`.
