# WatchLog 0.3.1

Fixes from the first day of 0.3 on the live demo.

## Fixed

- **RabbitMQ message rates:** the collector sent each node's global counters (split by protocol and queue type) as several values of one series, so publish, deliver and ack rates jumped (hundreds a second for 3). They are summed now. Upgrade the integrations collector; the history before the upgrade keeps the wrong rates.
- **A service's health follows its findings:** a critical finding (a queue with no consumers, 5 % 5xx) makes the service critical, a warning one at least warning, on the Applications list, the service page, the REST API and MCP. The list says which finding decides it (`finding` in the API, added).
- **"What WatchLog sees":** "orders has had no consumers since 09:58 (3 min ago)" in your time; no sentence can render a blank any more (tested for every finding of the four integrations). The Ready card and the finding give the same growth per minute.
- **Nginx:** no 5xx at all reads 0 %, not "—".
- **Only the content scrolls:** on macOS, scrolling to the end of a page no longer moves the sidebar, the top bar or the demo banner (the whole page rubber-banded).

## Upgrading

No manual steps. Kubernetes: `helm upgrade … --version 0.3.1 --reuse-values`. Docker: set `WATCHLOG_VERSION=0.3.1` and `docker compose pull && docker compose up -d` for the server; run the integrations collector's command again on hosts that run one.

MongoDB moves to 0.3.2.
