# WatchLog 0.1.0

The first public release of WatchLog Community: open-source monitoring for Kubernetes and Docker, with one agent.

## What ships

- **Kubernetes:** one Helm chart installs the backend, the web UI and the agents. It covers:
  - the cluster overview, nodes, workloads, pods with restart and OOM reasons, and events;
  - Kubernetes objects from a cluster-agent that watches the API, so nodes never need API access.
- **Docker hosts:** one `docker run` per host. Hosts, containers, health checks and why a container stopped.
- **Service map from eBPF:** who connects to whom, with connection rates, failures, connect latency, bytes and DNS errors.
  - No code changes and no sidecars.
  - External dependencies are named by DNS.
  - It needs Linux 5.8+ with BTF; other nodes show topology from Services and say why.
- **Alerts that work on day one:** default rules for crash loops, OOM kills, node pressure, failing connections, an agent that stopped reporting, and more. They go to Slack, Telegram, email or webhooks.
- **Read-only, least privilege:**
  - The node agent reads `/proc`, `/sys` and its kubelet, and loads eBPF programs with only `BPF` and `PERFMON`.
  - It never reads Secrets, ConfigMap data, environment values or request payloads.
  - See [what the agent can access](https://github.com/watchlog-light/watchlog/blob/v0.1.0/docs/site/security.md).
- **Self-hosted and free** for one cluster under AGPL-3.0. The images and charts are signed with cosign.

### Done in the last week before the release

- **The service map never shows a cluster Service as external** (ADR-116). The cluster-agent pushes address changes to the node agents, so a new Service's edges are right from the first data (measured: 14–36 s from creating the Service). An edge is red only while it had failures in the last minute.
- **Silent ingest failures are visible** (ADR-117). If WatchLog cannot store a cluster's data, the overview and Settings say "Data delayed: ingest failing since …", and the default rule "WatchLog ingest failing" alerts after 5 minutes. Agents count their failed requests.
- **A fresh install starts cleanly** (ADR-118): the backend and the alert-worker wait for PostgreSQL instead of restarting.
- **A consistent type scale** (ADR-115): 11 px only for uppercase labels and chart axes.

## Known limits

- One cluster per installation (Community). Cloud and multi-cluster come later.
- The service map needs eBPF with BTF (most kernels since 2020). Without it, nodes fall back to topology from Services.
- English only.

## Upgrading

Upgrades need no manual steps:

- `helm upgrade --reuse-values` from any earlier chart turns network flows on.
- A Docker agent is upgraded by re-running the install command.

Questions and problems: [GitHub Discussions](https://github.com/watchlog-light/watchlog/discussions) or an issue.
