# WatchLog 0.9.0

**Linux servers.** Install one command on a server and WatchLog shows everything it runs: every
systemd service, every process group (a pm2 app, a PHP-FPM pool, a Go binary, a jar or a script
started by hand, in any language) and every container, with their crashes, exit codes and OOM
kills from the kernel, alerts that say why, logs on demand and the network between them
([Linux servers](https://github.com/watchlog-light/watchlog/blob/v0.9.0/docs/site/servers.md)).
No code changes, no exporters.

Docker fleets become **Server fleets** and keep their history, tokens, rules and bill: the
upgrade migrates them by itself. Their 0.8 agents keep working; the 0.9 agent adds services
and processes. Monitoring stays free in every edition.

## What's new

- **Server fleets** (ADR-207). Two kinds of cluster: Kubernetes and Servers. The sidebar of a
  Server fleet says Servers and Workloads; 0.8's Hosts and Containers addresses redirect.
  - **Servers:** every server with its CPU, memory and disk, how many services, process
    groups and containers it runs, and what needs attention, problems first.
  - **A server:** its OS, kernel, systemd and Docker versions; its resources; one table of its
    workloads, process groups under the service they run in, with ports and restarts; its
    events; who it talks to.
  - **A workload:** a service's or process group's last hour of exits and restarts from the
    kernel, its releases marked, what it runs in or holds, its connections, its log on demand
    and **probable cause**: likely the release, its memory limit, a dependency or its CPU limit,
    with what was checked.
  - **Workloads** lists every workload of the fleet, all three sources.
  - **Phones:** every page as cards.
- **The agent's server mode** (ADR-208, ADR-210): systemd's units over D-Bus with each unit's
  cgroup (CPU, memory against `MemoryMax`, throttling at `CPUQuota`, tasks, I/O, restarts); the
  processes grouped by your rules, then pm2, supervisord, PHP-FPM, gunicorn and uwsgi, Java, the
  script and the executable; every exit's code or signal and OOM kills from one eBPF program;
  connections attributed to the service or group that opens them; listening ports. Command
  lines, arguments, environments and process ids never leave the server. About 490–680 series
  a server, 7–10 MB a day on Cloud, less than a Kubernetes node.
- **Install** (ADR-209): one command (`curl … | sudo sh`), a deb, an rpm or `docker run`. The
  agent runs as the user `watchlog` with five capabilities, not root; checksums always, and
  the release's cosign signature when `cosign` is installed. `--upgrade` and `--uninstall`.
  Tested on Ubuntu 24.04, Debian 12 and Rocky 9 with SELinux.
- **Process-group rules:** your own names, per fleet, under its settings, with a preview of a
  command line in the browser; the agents pick them up within a minute.
- **Applications on servers** (ADR-212): PostgreSQL, MariaDB and MySQL, Redis, MongoDB,
  RabbitMQ, Kafka, nginx and Traefik installed with apt or dnf are offered by their unit's name
  and read by the server's own collector on loopback.
- **New: PHP-FPM** ([PHP-FPM](https://github.com/watchlog-light/watchlog/blob/v0.9.0/docs/site/integrations/php-fpm.md)):
  busy and idle workers, requests waiting, pm.max_children reached, requests a second and
  request time, from each pool's status page over FastCGI; three default alerts.
- **Alerts** (ADR-213): nine default rules for servers: a service failed; a service or process
  group crash-looping; an OOM kill; a process group gone; a service at its memory limit or
  CPUQuota; the server's memory. Existing organizations get them by themselves.
- **Logs on demand** on servers: a service's journal, a pm2 app's or supervisord program's log,
  redacted on the server, never stored.
- **Right-sizing** for services with a `MemoryMax` or `CPUQuota`.
- **Egress watch and What changed** include services and process groups.
- **API and MCP:** `GET /clusters/:id/servers`, a server, its workloads and one workload, and
  `GET`/`PUT /clusters/:id/process-rules`; MCP `get_server` and `list_workloads` (Kubernetes
  too). The 0.8 Docker routes keep answering, for containers.

## Changed

- **The dashboard polls less, in every edition, on Kubernetes clusters and Server fleets.**
  Pages and panels that refresh pause while their browser tab is hidden and refresh as soon as
  it is visible again. Each refresh comes 20 % earlier or later at random, so tabs opened
  together don't ask in step, and the next one is planned only once the last one finished.
- **"Busy, retrying…" instead of an error.** When the server answers 429, or a 503 that clears
  by itself, a page keeps what it shows, says "Busy, retrying…" in the top bar, and tries again
  (after 2, 4, 8 … up to 30 seconds, never sooner than the server's Retry-After).
- **Static files for a CDN.** The web image serves `index.html` and the dashboard's routes with
  `Cache-Control: no-cache`, and its hashed files a year, as before. A missing hashed file is a
  plain 404.
- **Docker fleet is now Server fleet** everywhere: the API answers `kind: "server"` and accepts
  `docker` as an alias of it, as do MCP tools' arguments.

## The live demo (demo mode only)

- **One answer for every visitor.** In demo mode every visitor is the same read-only viewer, so
  the backend shares its answers: a page's data is asked of VictoriaMetrics once every 15
  seconds (`demoCache.seconds`, 5–60), however many people look, and identical requests in
  flight share one call, in a 64 MiB cache (`demoCache.maxMb`). Community and Cloud never share
  answers across requests.
- **Busy, not broken.** Past 16 cache misses to metric-backed pages at once
  (`demoCache.maxUpstream`), the next is answered at once with 503 and Retry-After.
- **Groups behind one address** can start 60 demo sessions a minute (20 before).

## Upgrading

No manual steps. One database migration turns Docker fleets into Server fleets and keeps their
ids, so tokens, rules, alerts, history and billing carry over; the series keep their labels.
Kubernetes: `helm upgrade … --version 0.9.0 --reuse-values`. Docker Compose: set
`WATCHLOG_VERSION=0.9.0`, then `docker compose pull && docker compose up -d`.

Agents: 0.8 agents keep sending containers and host metrics to their fleet. To see a server's
services and processes, install the 0.9 agent with the command under the fleet's **Add
servers**, or run its new `docker run` command (it adds `--cgroupns host`, the D-Bus socket and
three capabilities).
