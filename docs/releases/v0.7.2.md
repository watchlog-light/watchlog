# WatchLog 0.7.2

A security fix for WatchLog Cloud's plan limits and node counts (security review finding SR-8).

## Fixed

- **Node limits and billed nodes trusted what the agent said about itself.** A modified agent could send a node's data under another name in its `X-WatchLog-Agent` header (`cluster-agent`, for example) to pass the Free plan's 5-node limit, or report its heartbeat as the cluster-agent's to be counted as no node at all. Now:
  - **Kubernetes:** a node is counted by the `node` name on the metrics it sends and by the nodes the Kubernetes API lists (from the cluster agent). An agent on a node the API doesn't list is still accepted, and counted.
  - **Docker:** a host is counted by the `host` name on its metrics. A changed header doesn't move it, and a rename within the hour adds a host, never removes one.
  - **The limit:** a new node over the plan gets `402` by the node its data names (its metrics, heartbeat, Docker inventory and events), whatever the header says. Nodes already sending keep sending, as before.
  - **The bill:** each hour keeps two counts, the one the agents' heartbeats report and the one WatchLog sees, and bills the higher.

Community installations have no plans or limits and see no change.

## Upgrading

No manual steps: one automatic migration adds a table and four columns to the hourly usage. Earlier hours keep their counts; the new count starts at the upgrade. Agents don't change, and every agent version keeps working. Kubernetes: `helm upgrade … --version 0.7.2 --reuse-values`. Docker: set `WATCHLOG_VERSION=0.7.2`, then `docker compose pull && docker compose up -d`.
