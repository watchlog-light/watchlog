# WatchLog 1.2.1: the lock holder first

Two fixes found within minutes of 1.2.0 on the live demo.

## What's fixed

- **A query blocked on a lock is no longer the first finding.** When a session waited on
  another's row lock for 6 minutes, PostgreSQL's and MySQL's pages led with "A query has been
  running for 6 min", and the probable cause followed it: the victim, not the cause. When the
  longest running query is one that waits on a lock, the lock finding, naming the session that
  holds it, stands alone. The "query running longer than 5 minutes" alert is unchanged.
- **"Clients · 1 service"** (and "1 day") in the database pages' query flow, not "1 services".

## Upgrading

Nothing to do; no migration. The backend and web images only; the agent and collector are the
same as 1.2.0's.
