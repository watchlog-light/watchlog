# WatchLog 0.9.10

A small follow-up to 0.9.9: "Forgot your password?" works when Cloudflare is blocked, its
answer no longer hints at whether an account exists, WatchLog Cloud logs nothing about the
leaked-password check, and the password field leaves suggestions to your browser.

## Changed

- **"Suggest a strong password" is gone.** Browsers and password managers already suggest
  and save strong passwords, and ours was only four words from a list of 1,024 (about 40
  bits). The field still tells the browser it is a new password, so its own suggestion is
  offered; the live checklist, the errors under the field and show/hide stay. A leaked
  password's error now says "Pick a different one, or let your browser or password manager
  suggest one."

## Fixed

- **"Forgot your password?" answers in the same time for every address.** The reset email
  used to be sent before the answer, so the answer took longer when the address had an
  account (the email server needs a moment to accept a message). The link is now made and
  sent after the answer. This applies to self-hosted installs with email set up, too
  ([ADR-175](https://github.com/watchlog-light/watchlog/blob/v0.9.10/docs/DECISIONS.md)).

## WatchLog Cloud

- **"Forgot your password?" works when Cloudflare is blocked.** As with sign-in since 0.9.9,
  a reset request without the human check still goes through, limited to 5 per address typed
  and 10 per visitor address in 15 minutes. The address typed is counted whether it has an
  account or not, so the answer is the same either way. The dialog waits up to 3 seconds for
  the check, and no longer shows "could not load… reload the page".
- **Nothing about the leaked-password check is logged.** The page still sends only the first
  5 characters of the password's hash, limited to 60 lookups a minute per address; the server
  no longer writes those lookups to its log.

## Upgrading

No manual steps and no database migration. Agents are unchanged: 0.9.2 agents need no
upgrade.
