# WatchLog 1.0.4: SNMPv3 with DES and MD5, so a QNAP can be read

A patch release for network devices. A QNAP NAS encrypts SNMPv3 with DES and WatchLog offered
only AES, so it couldn't be read. Now every SNMPv3 protocol a device may offer can be chosen,
and the profile's test says which value is wrong.

## What's changed

- **More SNMPv3 protocols**
  ([docs](https://github.com/watchlog-light/watchlog/blob/v1.0.4/docs/site/network.md#snmpv3s-protocols),
  ADR-233). Authentication with SHA-256, SHA-1, SHA-224, SHA-384, SHA-512 or MD5; privacy
  with AES-128, AES-192, AES-256, Cisco's AES-192 and AES-256 (for IOS's `priv aes 192|256`) or
  DES; and the security level chosen in the form: authentication and privacy (the default),
  authentication only, or neither.
- **Honest about strength.** The choices are grouped into Recommended and For older devices
  (MD5, DES), and choosing MD5 or DES shows one calm line. A profile with MD5 or DES carries a
  small "older encryption" mark on its card and its devices' pages; one without privacy says
  "not encrypted". Nothing alerts on them. New profiles still start with SHA-256 and AES.
- **The test says which value is wrong:** the device doesn't know the user; the
  authentication password or protocol doesn't match; the device answered but the privacy
  protocol or password doesn't match ("if this is a QNAP, choose DES"); or the user has
  another security level.
- **Find what works.** With the passwords as typed, it tries the protocols against that one
  address, one request each, one at a time, and offers to set the profile to the first that
  answers. It never tries other passwords, users or addresses.
- **QNAP steps follow QTS's real screen**
  ([docs](https://github.com/watchlog-light/watchlog/blob/v1.0.4/docs/site/network.md#storage-a-qnap-nas)):
  SNMP V3, HMAC-SHA, Use Privacy, so the profile is SHA with DES. **New profile for a QNAP**
  starts the form with SHA and DES, and a QNAP that can't be read links to it. The UPS steps
  name each card's menu and protocols (APC, Eaton, CyberPower).

## What's fixed

- The docs said a QNAP used SHA with AES; QTS encrypts with DES.
- The NX-OS commands now say that a bare `priv` means AES-128 from NX-OS 10.1, not DES.

## Upgrading

Nothing to do; no migration. Existing profiles keep working unchanged. DES, MD5, Cisco's AES
and profiles without authentication need the 1.0.4 collector on the poller
([how](https://github.com/watchlog-light/watchlog/blob/v1.0.4/docs/site/network.md#updating-the-collector):
`install.sh --upgrade` on a server, the chart's new version in a cluster). An older collector
refuses such a profile, and the device's page and the profile's card say which server's
collector to update.
