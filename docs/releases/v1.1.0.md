# WatchLog 1.1.0: RabbitMQ, much stronger

RabbitMQ's page grows from four tabs of charts into a page you can run an incident from. Still
no RabbitMQ user, no management API, and WatchLog never reads messages.

## What's new

- **Overview**
  ([docs](https://github.com/watchlog-light/watchlog/blob/v1.1.0/docs/site/integrations/rabbitmq.md#what-you-see)):
  the finding first, with links to the queue and the workload and when memory reaches the high
  watermark at this rate; the **message flow** from publishers through exchanges and queues to
  consumers, with the rate between each; six tiles that say what is usual for this hour (with
  What changed); publish against deliver with what happened marked on it; ready by queue;
  **health checks**; the queues that need a look.
- **Queues:** every queue with its type (classic, quorum, stream), ready, unacked, in and out
  per second, consumers and how busy they are, and **drains in**. Sort, search, or only the
  queues with no consumer.
- **A page for each queue**, at its own address: depth against its usual range, in against acked
  and redelivered, how busy the consumers were before they left, **what happened** around it,
  the **probable cause**, its facts, and **its own alerts**, added in one click.
- **Clients:** every workload that connected to the broker in the last 24 hours, from the
  agents' network flows: connections, bytes each way, a "Mostly publishes / consumes" guess
  only where the traffic clearly says so, and how it ended.
- **Nodes:** each node against its limits (memory, disk, file descriptors, Erlang processes,
  sockets on 3.x), its version, queue leaders (4.x) and uptime; connection churn.
- **A new default alert:** a growing queue takes a node to its memory watermark within an hour.
  Rules can be scoped to one queue.
- **API and MCP:** the queues, one queue and the clients
  (`/applications/:id/rabbitmq/…`); `get_application` includes them for RabbitMQ.

Only what RabbitMQ really exports is shown. Network partitions, whether quorum replicas are in
sync, a queue's bindings and its dead-letter target aren't exported, so they aren't on the page
(ADR-243).

## What's fixed

- On RabbitMQ 3.13 the per-queue deliver column was empty: 3.13 keeps those counts per channel,
  and the agent now sums them.
- Streams and dead-letter queues no longer count as "queues that lost their consumers".

## Upgrading

Nothing to do; no migration. The new queue details (type, utilisation, Raft, exchanges, 3.13's
counters) need the 1.1.0 agent's integrations collector (`install.sh --upgrade` on a server, the
chart's new version in a cluster); with an older one the page shows what it already had.
