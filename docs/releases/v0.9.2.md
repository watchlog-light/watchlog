# WatchLog 0.9.2

**Events for Linux servers.** A server's services and process groups now have their own
events, stored and grouped like Kubernetes events, and the fleet's Events page is organized by
server and workload
([Linux servers](https://github.com/watchlog-light/watchlog/blob/v0.9.2/docs/site/servers.md#events)).

## What's new

- **A server's own events,** sent by the 0.9.2 agent as they happen:
  - **services:** Failed (systemd's result and exit code), Started, Stopped, Restarted,
    UnitChanged (its unit file changed on disk), OOMKilled (with its `MemoryMax`), Release;
  - **process groups:** FailedExit (its exit code or signal), CrashLoop and CrashLoopEnded,
    Appeared, Gone, OOMKilled (with the limit it hit, or the kernel's own), Release;
  - **containers,** as before.

  Repeated events are grouped like Kubernetes events: one row per workload and reason per day,
  with a count and the first and last time. An event names its unit or process group, never a
  pid or a command line.

- **The Events page for Server fleets:**
  - the top bar filters by server and by workload;
  - the facets are Kind (Service, Process, Container), Server, Workload and Reason, with the
    Compose project once Container is ticked;
  - **Hide system** is on by default, as on the Workloads page;
  - each row opens its workload's page;
  - crash loops and releases are marked on the chart;
  - the empty states say why there is nothing to show.
- **Other pages use the same events:**
  - a server's page lists its last 24 hours of events and links to the rest;
  - a workload's page lists its own events;
  - the Overview's warning events open the service or process group.
- **API and MCP:** `GET …/events` takes `workloads=` (`service:<unit>`, `process:<group>`,
  `container:<name>`) and `system=hide`, and each event carries its `workload`. MCP
  `get_events` takes `workload` and `kind`.

## Fixed

- A server's page no longer shows a failed or OOM-killed workload twice in its events, and
  leaves out the OS's own workloads, as the Events page's Hide system does.
- A service's OOM kills count any of its processes: a child killed at the unit's `MemoryMax`
  (a shell's command, a worker) was missed when it wasn't the main process.
- The agent builds on macOS again (its eBPF stub outside Linux).

## Measured

On Ubuntu 24.04 with nginx, PHP-FPM, two pm2 apps, supervisord, a Go service, a jar and Redis
in Docker, against a running WatchLog: each of a pm2 app killed (`killed by SIGKILL (9)`), a unit
failing (`failed (exit-code, exit code 3)`), a unit OOM-killed under a 64 MiB `MemoryMax`
(`OOM-killed at its MemoryMax of 64 MiB`) and an executable replaced (`Release`) was on the Events
page within a minute. No stored event carried a command line, and Hide system kept the workloads'
events and dropped WatchLog's own. Screenshots at 390, 1280 and 1440 px.

## Upgrading

No manual steps and no database migration. Install the 0.9.2 agent on your servers
(`curl -fsSL https://<your WatchLog>/install.sh | sudo sh -s -- --upgrade`, or the deb or
rpm) to get service and process group events. A 0.9.0 or 0.9.1 agent keeps working:

- its containers' events still show;
- its server page works its events out from the counters, as before, and says that the agent
  needs upgrading.
