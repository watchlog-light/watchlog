# WatchLog 1.3.0: a guided tour of the live demo

The [live demo](https://demo.watchlog.io/demo) now shows a first-time visitor where to look.
In 30 seconds it walks one real, open incident: the problem, why it happened, the proof, and how
to get the same on your own systems.

## What's new

- **A 30-second tour, on the side you run.** "Kubernetes or Linux servers?" first, then four
  steps on the demo's real pages: the problem's row on All clusters and fleets, the alert's
  **probable cause**, its chart and What changed, and the end card with the install command
  for that side and a link to WatchLog Cloud.
- **Live, never recorded.** The tour tells the first open incident in the demo's own order
  that has a Likely cause. If none is open, it tells a failure that never heals: a crash-looping
  importer on Kubernetes, or a service that fails after each release on the server. Nothing is
  recorded or faked; the cards' words are the only fixed text. "Or see another one" offers the
  others that are open.
- **When it opens:** on a first visit; from the demo banner's "Replay the 30-second tour"; and
  straight at step 1 from a link with `?tour=k8s` or `?tour=servers`. `?tour=off` never opens
  it. Esc or Skip closes it, the arrow keys move between steps, and nothing advances by itself.
  On phones it is a bottom sheet.
- **Only in the live demo.** Self-hosted installs and WatchLog Cloud never load it, and its
  routes answer 404 outside demo mode (ADR-246).

## Upgrading

Nothing to do; no migration. The backend and web images only; the agent and collector are the
same as 1.2.1's. A demo kit's seed may list the tour's stories (`demoTour`); without them the
demo shows no tour.
