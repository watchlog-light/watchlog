# WatchLog 0.1.2

The dashboard works on phones, nodes that are containers show only themselves, and a read-only demo mode makes a public live demo possible.

## Security

- `GET /settings/telegram` returned the Telegram proxy URL, including any password in it, to every signed-in user, viewers included (0.1.0–0.1.1). Passwords in proxy and webhook URLs now show as `****`. If you set a Telegram proxy with a password, change that password.

## What's new

- **Phones and tablets** (ADR-120): below 1024 px the sidebar is a drawer; below 768 px wide tables become cards, the cluster, filters and time range share one sheet, pickers open as sheets, and the service map opens on its Connections list and pans and zooms by touch. Touch targets are at least 44 px.
- **Nodes that are containers** (kind, k3d, LXC; ADR-121):
  - **Pod filter:** the kernel records connections and DNS queries only of the node's own pods. Processes and containers next to the cluster are never recorded, only counted. It is on by default; measured, it makes the agent cheaper, not dearer.
  - **`agent.nodeMetricsScope`** (`host`, `cgroup`, `auto`): in cgroup scope a node's CPU, memory, disk I/O and boot time come from its own container, and its capacity is the container's limits, not the machine's. `auto` picks it for nodes that are containers.
- **Read-only demo mode** (ADR-122): `demoMode: true` lets anyone look at an installation without an account. Every change is refused on the server, secrets are never shown, and queries are capped at 24 hours and rate-limited per visitor.
- **Seed file** (`seed` in the chart): alert rules created at start, once, by name, so an installation can be configured from its values.
- **Behind a reverse proxy** (ADR-123):
  - **Trusted proxies:** `backend.trustedProxies` lists them, and `backend.clientIpHeader` names the visitor's address for the rate limits, believed only from those proxies.
  - **Secure cookies:** the session cookie is Secure whenever the request came over https. `cookieSecure: auto|always|never` overrides it.
  - See "Behind a reverse proxy" in the [configuration guide](https://github.com/watchlog-light/watchlog/blob/v0.1.2/docs/site/configuration.md).

## Known limits

- Nodes in cgroup scope report no filesystem sizes, so their disk usage column and the disk usage rule stay empty.
- One cluster per installation (Community). English only.

## Upgrading

Upgrades need no manual steps: every new chart value is optional, and `helm upgrade --reuse-values` keeps working. Behind a TLS proxy that sends `X-Forwarded-Proto: https`, session cookies become Secure at the next sign-in.

Questions and problems: [GitHub Discussions](https://github.com/watchlog-light/watchlog/discussions) or an issue.
