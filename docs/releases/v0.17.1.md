# WatchLog 0.17.1: device pages per kind, and the demo's ranges

A patch release for the network device page and the live demo.

## What's fixed

- **A device's page shows only what the device reports.** A Wi-Fi access point read through
  CAPsMAN has no CPU, memory, temperature or ports to read, so its page no longer draws empty
  tiles and charts for them: it shows its clients now, its radios with band and channel, its weak
  clients, and its clients over the chosen range. A UPS shows its charge, runtime and load; a
  recorder whether it is recording, its cameras and the days of recording left. Switches, routers
  and the NAS show CPU, memory and temperature when their profile reads them. An access point's
  header says "CAPsMAN on <router>" instead of an empty profile.
- **The demo offers only ranges it can show.** The demo answers at most the last 24 hours; a
  device's page and an application's page offered 7 days there and showed broken charts. The
  backend now tells the dashboard its limit, and no page offers more.
- **A chart says why it can't be drawn.** When the server refuses a chart's request and explains
  why, the chart shows that explanation instead of "couldn't be loaded", without a Retry that
  would get the same answer.
- **The status pill.** "Up" in amber meant the device had open alerts (on the demo's
  `ap-warehouse`, two 2.4 GHz channel-overlap warnings). The pill now shows the device's own
  state in its own colour, and the open alerts as a separate count beside it.
- **Probable cause sees older releases.** A server's service or process group "last release"
  query used a function VictoriaMetrics doesn't have, so a release more than an hour before the
  page's window was missed.

## Upgrading

Nothing to do; no migration. Agents and collectors need no update.
