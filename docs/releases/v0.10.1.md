# WatchLog 0.10.1

A tidier sidebar and three fixes: an Nginx on a Linux server shows its requests, errors and
latency again, a service no longer says Healthy without any numbers, and a new Server fleet's
empty pages speak about servers, not Kubernetes.

## Changed

- **The sidebar's footer is two rows.** Your name is now one button, "Account, tokens, sign
  out", that opens a menu: who is signed in (the whole email address), then API tokens,
  Documentation and Sign out; WatchLog Cloud adds Account and security and Plan and billing,
  and the organization, role and plan. It works from the keyboard (arrow keys, Esc, focus back
  on the button). The separate Sign out row is gone.
- **Collapse is next to the logo.** The collapsed sidebar keeps the logo, the expand button,
  the icons with their names on hover and, at the bottom, your avatar, which opens the same
  menu to the right. Whether it is collapsed is remembered as before. The phone menu has the
  same footer.
- **Healthy needs a number.** A monitored service shows Healthy only when at least one of its
  key numbers has data. One the collector reaches but that sends no numbers shows **No
  metrics**, with the one step that fixes it: the integration's own (stub_status for an
  HTTPS-only Nginx, ingress-nginx's or Traefik's metrics, RabbitMQ's Prometheus plugin,
  PHP-FPM's status page), else the collector's log on that server or in the cluster. The first
  five minutes after Monitor read as waiting. The list, the service's page, the REST API
  (reason `no_metrics`) and MCP agree. Kubernetes and servers alike.

## Fixed

- **Nginx on a Linux server shows its requests, errors and latency.** For an Nginx installed
  on a server (not in a container), WatchLog didn't select the agent's eBPF numbers, so the
  Applications row showed three dashes next to Healthy. They are now read by the nginx unit
  (or process group) and its port, as the rest of WatchLog does; Traefik's eBPF fallback on
  servers gets the same fix. An Nginx with stub_status but only HTTPS traffic shows its active
  connections as its number.
- **A new Server fleet's pages talk about servers.** Its empty Overview says it is waiting for
  the first server, with the install command for servers (the script, a deb or rpm package, or
  docker run), not the helm command. An empty Service map on a fleet without eBPF says what
  the map needs on servers instead of naming Kubernetes Services. Egress, Events and
  Applications name services, processes and containers.
- **"Kubernetes and servers".** The Applications subtitle and the API tokens chip no longer
  say "Kubernetes and Docker"; the logs-on-demand page's table covers servers' services and
  process groups.

## WatchLog Cloud

- **The plan is one compact row.** Free shows "Free · 3 of 5 nodes" with a thin bar (in the
  warning colour from 4 of 5) and "Upgrade →", and the whole row opens Plan and billing. Pro
  shows its label and "9 servers · 30 days of data" ("nodes" when every cluster is a
  Kubernetes cluster), with nothing to upsell. Community has no plan row.

## Upgrading

No manual steps and no database migration. Agents are unchanged: 0.10.0 agents need no
upgrade.
